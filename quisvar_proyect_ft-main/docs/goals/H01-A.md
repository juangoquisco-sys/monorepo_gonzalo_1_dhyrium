# H01-A histórico — DOCX y sesiones de Microsoft Word

> **Sustituido por H01-WEB / REV-33–35 el 11 de agosto de 2026.** Este objetivo se conserva únicamente como registro técnico. El producto canónico usa Dhyrium Writer web independiente y no depende de Microsoft Word, Office, WebDAV ni `ms-word:` para editar.

Estado: launcher y shell implementados en desarrollo; E2E con Word real pendiente  
Contrato: `PLAN.md`, flujo documental canónico  
Entorno autorizado: desarrollo (`172.16.10.177`)  
Producción (`172.16.10.250`): fuera de alcance y no modificada

## Objetivo

Abrir un DOCX real desde una tarea sin convertirlo a HTML/Canvas, conservar el
original como referencia protegida, editar el binario en Microsoft Word y
guardar cada resultado como una versión nueva sin sobrescribir el adjunto.

## Alcance implementado

- bóveda inmutable de versiones DOCX;
- importación controlada del adjunto como `ORIGINAL_IMPORT`;
- autorización por rol del módulo Proyectos o asignación de tarea;
- una sesión editable activa por documento, con lease y TTL;
- token aleatorio temporal almacenado únicamente como hash;
- canal WebDAV temporal inicial para Microsoft Word de escritorio;
- guardado `PUT` con validación DOCX mínima y creación de una nueva versión;
- descarga Word/PDF, historial y restauración no destructiva;
- selector inicial del DOCX sin Canvas y original protegido como consulta
  auxiliar;
- contenido Canvas heredado conservado sin migración destructiva.

## Fuera de alcance

- modificar el archivo adjunto original;
- editar DOCX complejos mediante HTML o Canvas;
- habilitar producción sin HTTPS confiable y pruebas de capacidad;
- declarar paridad visual sin una ejecución real del documento en Word.

## Criterios de cierre

1. El DOCX se importa sin cambiar su SHA-256.
2. La vista inicial selecciona el DOCX y no monta el editor Canvas.
3. `Editar en Word` emite `ms-word:ofe|u|URL` para una sesión autorizada; el
   cierre requiere evidencia posterior de actividad real en Word.
4. Un `PUT` con firma ZIP y marcador OOXML crea una versión nueva; contenido
   arbitrario se rechaza y la validación OPC completa queda como compuerta.
5. Restaurar crea una versión adicional y nunca reemplaza el original.
6. Una segunda sesión concurrente se rechaza y los tokens expiran.
7. No existen dependencias, rutas ni servicios de edición web externos.

## Estado verificado

El backend, el esquema local y la interfaz se redujeron al flujo Word. Las
pruebas de dominio, esquema y middleware validan tokens, identidad del adjunto,
permisos, proveedor único y la validación previa al cuerpo PUT. La prueba
Playwright valida el shell y que Canvas no se monte por defecto. La evidencia
técnica vigente se mantiene en `../quality/H01-A_DOCUMENT_SESSION_EVIDENCE.md`.

La paridad de paginación sigue dependiendo de Microsoft Word, las fuentes y la
configuración de impresión de la estación. No se afirma paridad visual hasta
capturar y comparar el fixture real de extremo a extremo.
